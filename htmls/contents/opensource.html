สู่โอเพนซอร์ส
ทำไม?
> หลายเหตุผล เหตุผลหลักคือการเป็นต้นแบบให้ผู้พัฒนาเกมหน้าใหม่ได้ทดสอบและทำไอเดียของตนได้ง่าย ให้ผู้เล่นเห็นสิ่งที่อยู่เบื้องหลังและเรียนรู้จากประสบการณ์
ความฝัน
> ถ้าคุณอ่าน /r/MMORPG บน Reddit การสนทนามีรูปแบบชัดเจน มีกลุ่มผู้เล่นที่มีความต้องการและความคาดหวังต่างกัน เนื่องจากความต้องการเวลา/พลังงาน/เงินที่มหาศาลในการพัฒนา MMORPG ผู้พัฒนาจึงมักตอบสนองความต้องการไม่ได้ ไม่มีโอกาสได้ลองสิ่งใหม่ MMORPG ส่วนใหญ่ตีถูกครั้งเดียวแล้วพลาด เกมที่ฉลาดดูเหมือนจะใช้การระดมทุน
> By almost eliminating the entry barrier to MMORPG development, I hope to give birth to the PUBG of MMORPG's. Where indie developers start by modifying จตุรธาตุ's Code to implement their ideas, unique dynamics and mechanics. Create a working formula. Get investment, make money, crowdfund, develop their idea from scratch and come up with an MMORPG that works.
ตัวอย่างบางส่วน
> จตุรธาตุ มีโหมดฮาร์ดคอร์ ดรอป/รางวัล XP สูงลิบลิ่ว PVP โหดร้าย เซิร์ฟเวอร์ฮาร์ดคอร์รันเพียงวันเดียว เกมเพลย์ที่ได้น่าดึงดูดกว่า เน้น AFK น้อยลง และแข่งขันสูงมาก บางครั้งฉันก็สงสัยว่าเกมเพลย์จริงควรเป็นแบบนี้ไหม แต่ในสภาพที่เป็นอยู่ จตุรธาตุ is at a point of no return too. After a certain point in an MMORPG's life, it's impossible to make such drastic changes.
>ในฐานะคนคลั่งไคล้แนวโร้กไลก์ ฉันใฝ่ฝันอยากเพิ่มองค์ประกอบโร้กไลก์ให้เกมเสมอ อาจเป็นดันเจี้ยน หรือเควสต์ที่เล่นซ้ำได้พร้อมขั้นตอนและผลลัพธ์สุ่ม พิจารณาความพยายามที่ต้องใช้เพื่อให้มันมีความหมายและสมดุล ไอเดียเหล่านี้จึงไม่เคยพัฒนา แต่ถ้าเริ่มจากศูนย์และลงทุน 2-3 เดือน เป็นไปได้มากที่จะพัฒนาเกมโร้กไลก์ออนไลน์ที่ไม่เหมือนใคร เช่น โร้กไลก์ที่เล่นกับปาร์ตี้ 4 คน
เทคโนโลยี
>จตุรธาตุ has been developed completely from scratch, even the map editor is a custom in-house one. The backend uses App Engine with Python, it's completely auto scalable. The code is simple and robust. Characters are saved, synced and loaded from the backend. All account operations are on the backend.
>สำหรับเซิร์ฟเวอร์เกม ใช้ Node, Javascript และ Socket.io ทุกอย่างเป็นโค้ดเขียนเองและเรียบง่ายที่สุดเท่าที่จะเป็นไปได้ เนื่องจากเป็น Javascript สไตล์โค้ดอาจไม่ถูกใจทุกคน แต่ใครก็ตามที่มีความรู้ Javascript เล็กน้อยก็เข้าใจได้ง่ายและหาโค้ดเจอเร็ว ตัวอย่างเช่น โค้ดซื้อของอยู่ใน handler `socket.on('buy',function(){})`
>Using Node and Javascript has enormous advantages, since there is no parallelism, coding is easy and there are no loopholes produced from parallel execution scenarios. However, it also caps the size of a single server. With a game like จตุรธาตุ, it can become a feature rather than a bug. As servers can just grow in number such as Europas I, II, III and so on. It would be possible to extend จตุรธาตุ to use multiple servers for a single game world, however, there's no reason to do so, it's best to keep things as simple as possible.
>On the Client side of things, จตุรธาตุ uses PIXI to draw things, no game engine is used and everything is as low level as possible. Animating characters, rendered weapons and attack animations is a dream for จตุรธาตุ 2. However if a group of developers invested 3-4 months onto the current codebase, it would truly enhance the gameplay and make the resulting product much more monetizable.
>ไคลเอนต์เกมใช้ Electron และแต่ละตัวมีการผสานที่เฉพาะตัว ฉันมีแผนพัฒนาเวอร์ชันมือถือแบบฮาร์ดคอร์/อายุสั้นด้วย ทั้งหมดนี้และเอกสารเกี่ยวกับไคลเอนต์เกมจะถูกเปิดเป็นโอเพนซอร์สเช่นกัน
ทรัพย์สิน ข้อมูล และลิขสิทธิ์
>จตุรธาตุ has unique/in-house assets, purchased assets and derivatives. When the game is open sourced, it will also be possible to download and copy all the game data, for example the maps. Developers will also have the opportunity to release the game as a sub-entity of จตุรธาตุ. For example, จตุรธาตุ: The Reckoning. This way, if a developer doesn't have the resources to track/purchase all the assets individually, it will be possible to release the game commercially as it will technically be owned by จตุรธาตุ. However it's best to just start from scratch and create everything in-house if possible. It's something I dreamed of but couldn't achieve.
เชิงพาณิชย์ ลิขสิทธิ์แบบเบา
> ในขณะที่รายละเอียดยังไม่กำหนด เกมจะถูกเปิดโอเพนซอร์สด้วยไลเซนส์เชิงพาณิชย์แบบกำหนดเอง ใช้ฟรีสำหรับการใช้งานไม่แสวงหากำไร เช่น การสร้างอินสแตนซ์/เซิร์ฟเวอร์ในบ้าน สำหรับผลงานเชิงพาณิชย์ จะมีข้อคาดหวังให้ได้รับ 12.5% จากรายได้รวม อย่างไรก็ตาม หากเกมประสบความสำเร็จและถูกเขียนใหม่จากศูนย์ (เหมือน pubg ที่เติบโตจาก arma) ไลเซนส์เชิงพาณิชย์จะไม่ครอบคลุมตัวใหม่ ฉันเชื่อว่า 12.5% เป็นเปอร์เซ็นต์ที่ยุติธรรมที่ผู้พัฒนายอมจ่าย ฉันยังวางแผนโปรโมทผลงานต่อยอดแต่ละตัวจากเกมหลักด้วย (ตอนนี้มันคือความฝัน หวังว่าจะเป็นจริง)
