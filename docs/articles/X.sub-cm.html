CODE messages

CODE messages, or CMs, send JSON-serializable data between characters. Server delivery stays within the current game server; it does not cross from one region/server to another. Characters opened locally can also receive a fast local delivery.

async function send_orders() { try { var result = await send_cm(["Wizard", "Protector"], { task: "move", map: character.map, x: character.x, y: character.y }); game_log("Delivered to: " + result.receivers.join(", ")); } catch (error) { // Locally delivered names remain listed if server delivery failed. game_log("CM failed: " + error.reason); } } send_orders();

send_cm returns one Promise. It fulfills with {receivers, locals}. Offline or missing server recipients are simply absent from receivers. If local delivery succeeds but server delivery fails, the rejection retains those names in locals and receivers so retry logic does not duplicate their message.

Receive messages through the character event:

character.on("cm", function (data) { if (data.name != "Wizard") { safe_log("Ignored CM from " + data.name); return; } show_json(data.message); });

The payload is {name, message}. Treat every incoming message as untrusted input: verify data.name, validate the message shape and allowed commands, and use safe_log when displaying untrusted text.

Messages must survive JSON.stringify. Do not send functions, circular objects, DOM nodes, or live entity objects. Copy only the primitive fields the receiver needs. Larger server-routed messages consume more communication capacity; batching recipients in one call is cheaper than repeating the same call.
