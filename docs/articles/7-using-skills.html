In Code, skills are referenced by their keys from: G.skills

One example is "supershot" you can check out: G.skills.supershot

async function use_supershot() { var target = get_nearest_monster(); if (!target) return; if (!is_in_range(target, "supershot")) return; if (is_on_cooldown("supershot")) return; try { var result = await use_skill("supershot", target); game_log("Supershot accepted"); return result; } catch (error) { game_log("Supershot failed: " + error.reason); } } use_supershot();

use_skill returns one Promise for the server response to the skill request. Client checks such as is_in_range and is_on_cooldown avoid obviously invalid calls; the server remains authoritative for class, equipment, target, MP, range, cooldown, conditions, and any skill-specific rules.

use_skill("invis"); use_skill("mluck", get_player("LuckyCharacter"));

Reference functions: use_skill is_in_range is_on_cooldown

Special Usage: 3-Shot

async function use_three_shot() { var targets = []; for (var id in parent.entities) if (parent.entities[id].type == "monster" && is_in_range(parent.entities[id], "3shot") && targets.length < 3) targets.push(parent.entities[id]); await use_skill("3shot", targets); } use_three_shot();

Special Usage: Controlled Burst

async function use_controlled_burst() { var targets = []; for (var id in parent.entities) if (parent.entities[id].type == "monster" && is_in_range(parent.entities[id], "cburst")) targets.push([parent.entities[id], 100]); await use_skill("cburst", targets); } use_controlled_burst();

Special Usage: Blink

use_skill("blink", [character.x + 10, character.y + 10]);

Multi-target skills still return one aggregate Promise, not an array of Promises. For ordinary skills, a fulfilled request means the server accepted that complete skill call; inspect the returned data for skill-specific results.

Pickpocket, fishing, and mining are timed actions. Their existing use_skill Promise deliberately remains backward compatible and resolves with in_progress: true when the action starts. Use use_skill_complete when later code depends on the actual result:

async function fish_once() { try { var result = await use_skill_complete("fishing"); if (result.found === false) game_log("Nothing caught this time"); else game_log("Caught something"); } catch (error) { game_log("Fishing failed: " + error.reason); } } fish_once();

The completion-safe form correlates the final event to its own request and removes its temporary listeners after success, failure, disconnect, or timeout. It defaults to 20 seconds, long enough for the declared fishing and mining durations. For every other skill it delegates directly to use_skill.
