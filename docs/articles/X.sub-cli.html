CLI runtime

The bundled CLI is an advanced Node.js runner for characters without the ordinary graphical client. Its reference implementation lives under scripts/cli and uses one worker per character.

CLI availability and account requirements are enforced by the server and can change. Check the current in-game CLI response before purchasing or configuring access; do not copy an old numeric price from a guide.

Runtime differences

if (game.cli) { game_log("Running through the CLI"); }

The CLI supplies the same core CODE routines and sets game.cli. There is no ordinary rendered game page, and browser-only UI or PIXI assumptions may not work. Keep gameplay logic platform-neutral and guard CLI-specific integration explicitly.

Worker messages

The host can place data into CLI_IN. CODE receives it as the clim character event:

character.on("clim", function (data) { show_json(data); });

CODE can send structured data back to the host through parent.CLI_OUT:

if (game.cli) { parent.CLI_OUT.push({ type: "status", data: { map: character.map, x: character.x, y: character.y } }); }

Treat CLI_IN, CLI_OUT, and host-defined message types as an interface between your runner and CODE. Keep payloads JSON-serializable and validate them on both sides.

Node access

The reference host injects cli_require into its emulated window. This is privileged Node.js access, not a portable public CODE routine. Use it only in code you control, keep credentials outside tracked source files, and never load untrusted CODE in a privileged CLI process.

The CLI scripts are a reference implementation rather than a zero-configuration launcher. Review their dependency and startup instructions in the checked-out version, supply configuration through local secrets, and test one character before starting several workers.
