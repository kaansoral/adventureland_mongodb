Server Status

server.status is the live, read-only view of server-wide events, special monsters, schedules, and temporary server effects.

show_json(server.status);

The object is updated for the server you are currently connected to. Entries appear and disappear as events start, change, and finish. A missing entry normally means that status is inactive.

Static definitions and live state

G.events.franky // Static event definition server.status.franky // Franky's current state on this server

G.events describes how an event is configured. server.status tells you what is happening now. The server makes the final validation decision.

Reading an event

var franky = server.status.franky; if (franky && !get_nearest_monster({ type: "franky" })) { join("franky"); }

Read server.status again after waiting or completing an asynchronous action. The game can replace the underlying data whenever a server update arrives, while server.status always returns the newest version.

var franky = await wait_for(function () { // This reads the newest status on every poll. return server.status.franky; }, 60000);

Special monster entries

Live bosses commonly expose the following fields. Event-specific entries can contain fewer fields or add their own.

{ live: true, map: "level2w", x: 120, y: -240, hp: 750000, max_hp: 1000000, target: "Wizard", end: new Date() }

live reports whether the monster is currently present. map, x, and y locate it when the event publishes exact coordinates. hp, max_hp, and target describe its latest broadcast combat state. end is the scheduled event end.

A scheduled special monster can instead publish spawn with live: false. Some roaming or hidden encounters intentionally omit coordinates.

Event-specific entries

server.status.goobrawl.end server.status.abtesting.signup_end server.status.abtesting.A server.status.abtesting.B

Event objects can expose timers, signup windows, scores, routes, choices, or other event-specific fields. Read the active entry and its event guide instead of assuming every event looks like a boss.

Schedule

server.status.schedule = { time_offset: 0, dailies: [13, 20], nightlies: [23], night: false };

schedule contains server clock information used by daily and nightly systems. Values can differ by server region.

Seasonal and temporary state

server.status.holidayseason server.status.halloween server.status.lunarnewyear server.status.valentines server.status.egghunt server.status.blessed_by server.status.blessed_minutes

Seasonal entries are usually truthy while their season is active. Temporary server effects can expose their source and remaining duration.

Compatibility

parent.S is the existing low-level form and remains supported. Prefer server.status: it has a clearer name and avoids holding an old status object by accident.

server.status.franky // Preferred parent.S.franky // Compatible legacy access

Do not add, remove, or modify status fields. Client-side changes do not affect the server and can mislead your own CODE until the next update.
