MessagePack socket transport

Custom clients can use an optional MessagePack Socket.IO connection. It carries the same game events and JSON-compatible values with smaller binary frames. The ordinary client and existing custom clients continue to use the normal socket path; no migration is required.

This transport is for standalone clients and integrations outside character CODE. Character CODE already uses the game's active connection and cannot replace its parser.

Each server directory entry provides two paths:

server.path // Normal Socket.IO transport server.msgpack_path // Optional MessagePack transport

External clients can retrieve the current server directory from the API. Browser-only clients should have their host supply the selected entry:

https://adventure.land/api/get_servers

Select one response entry and use it as server in the examples below. The official game page keeps its server directory in X.servers; external clients should use the API instead.

The MessagePack path is a separate endpoint. A connection must use its matching parser from the first packet onward. Do not connect a normal Socket.IO parser to msgpack_path, and do not use the MessagePack parser with path.

Browser client

The parser is specific to Adventure Land's positional format. Generic Socket.IO MessagePack parsers are not compatible. Download the Adventure Land parser, or load it directly after Socket.IO:

<script src="https://adventure.land/js/socket.io/4.2.0/socket.io.min.js"></script> <script src="https://adventure.land/js/socket.io-msgpack-parser.min.js"></script> <script> var options = { path: server.path, transports: ["websocket"] }; if (server.msgpack_path) { options.path = server.msgpack_path; options.parser = ALMsgpackParser; } var socket = io("https://" + server.address, options); </script>

The fallback is intentional: a custom client can still connect to a server that does not advertise the optional endpoint.

Node.js client

Download the same parser beside your external client. It also exports a CommonJS module:

curl -fsSLo socket.io-msgpack-parser.min.js https://adventure.land/js/socket.io-msgpack-parser.min.js
const { io } = require("socket.io-client"); const msgpackParser = require("./socket.io-msgpack-parser.min.js"); function connectToServer(server) { const options = { path: server.path, transports: ["websocket"] }; if (server.msgpack_path) { options.path = server.msgpack_path; options.parser = msgpackParser; } return io("https://" + server.address, options); }

Use the parser file shipped by Adventure Land so the wire format stays exact. Authentication, acknowledgements, event names, and event payloads are otherwise unchanged.

Format and limits

Each Socket.IO packet is one positional MessagePack array:

[0] or [0, data] // Connect [1] // Disconnect [2, data] // Event [2, id, data] // Event with acknowledgement [3, id, data] // Acknowledgement [4, data] // Connection error

The root namespace is implicit, and packet field names are not sent. For example, socket.emit("hello", "you") becomes [2, ["hello", "you"]]: 13 bytes instead of 17 with the normal JSON frame or 29 with a generic MessagePack packet map.

Most game events use less bandwidth because MessagePack stores numbers and collections compactly while the positional envelope stays small. Exact savings depend on the payload; WebSocket and TLS framing are unchanged.

Payloads follow JSON behavior: use strings, finite numbers, booleans, null, arrays, and ordinary objects. Dates become ISO strings; undefined object properties are omitted; undefined array entries and non-finite numbers become null. Binary values, MessagePack extensions, BigInt, circular objects, custom namespaces, and reserved Socket.IO event names are rejected.

The optional endpoint is WebSocket-only and accepts at most 64 KiB in a client packet. Keep messages small and use the normal game event flow. A parser error closes only that connection; reconnect with the same parser and path rather than changing parsers on an open socket.
