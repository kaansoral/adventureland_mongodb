MessagePack socket transport

Custom clients can use an optional MessagePack Socket.IO connection. It carries the same game events and JSON-compatible values with smaller binary frames. The ordinary client and existing custom clients continue to use the normal socket path; no migration is required.

Each server directory entry provides two paths:

server.path // Normal Socket.IO transport server.msgpack_path // Optional MessagePack transport

On the game page, the server directory is X.servers. Each entry contains fields including key, region, name, address, path, and msgpack_path. Select the entry your client intends to connect to. To find the currently selected server on an Adventure Land game page:

var server = X.servers.find(function (entry) { return entry.address == server_address && entry.path == server_path; }); if (!server) throw new Error("Selected server was not found in X.servers");

Inside character CODE, get_servers() returns the same cached server directory. The transport example below is for a custom client or host page; ordinary character CODE should use its existing game connection.

The MessagePack path is a separate endpoint. A connection must use its matching parser from the first packet onward. Do not connect a normal Socket.IO parser to msgpack_path, and do not use the MessagePack parser with path.

Browser client

Load Socket.IO first, then the Adventure Land parser:

<script src="/js/socket.io/4.2.0/socket.io.min.js"></script> <script src="/js/socket.io-msgpack-parser.min.js"></script> <script> var options = { path: server.path, transports: ["websocket"] }; if (server.msgpack_path) { options.path = server.msgpack_path; options.parser = ALMsgpackParser; } var socket = io(server.address, options); </script>

The fallback is intentional: a custom client can still connect to a server that does not advertise the optional endpoint.

Node.js client

The same generated parser file also exports a CommonJS module. Pass the entry selected from the server directory into the connection function:

const { io } = require("socket.io-client"); const msgpackParser = require("./socket.io-msgpack-parser.min.js"); function connectToServer(server) { const options = { path: server.path, transports: ["websocket"] }; if (server.msgpack_path) { options.path = server.msgpack_path; options.parser = msgpackParser; } return io(server.address, options); }

Use the parser file shipped by Adventure Land so the wire format stays exact. Authentication, acknowledgements, event names, and event payloads are otherwise unchanged.

Format and limits

One Socket.IO packet becomes one MessagePack array. For example, socket.emit("hello", "you") is encoded as [2, ["hello", "you"]]. It is 13 bytes instead of the normal 17-byte JSON frame.

Payloads follow JSON behavior: use strings, finite numbers, booleans, null, arrays, and ordinary objects. Dates become ISO strings; undefined object properties are omitted; undefined array entries and non-finite numbers become null. Binary values, MessagePack extensions, BigInt, circular objects, custom namespaces, and reserved Socket.IO event names are rejected.

The optional endpoint is WebSocket-only and accepts at most 64 KiB in a client packet. Keep messages small and use the normal game event flow. A parser error closes only that connection; reconnect with the same parser and path rather than changing parsers on an open socket.
