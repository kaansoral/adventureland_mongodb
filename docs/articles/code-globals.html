CODE globals

These objects are supplied to every character CODE context. Treat them as live read-only inputs unless a documented option explicitly invites configuration.

character

Your live character proxy: stats, inventory, equipment, conditions, action progress, movement, social state, and event methods. See the Character Object reference.

G

Static and server-supplied game definitions. Common collections include:

G.items // Item definitions G.skills // Skill definitions G.conditions // Condition definitions G.classes // Class definitions G.monsters // Base monster definitions G.maps // Maps, NPCs, doors, spawns, and monster packs G.npcs // NPC definitions G.events // Joinable and announced event definitions G.craft // Craft recipes G.tokens // Token exchange tables G.projectiles // Projectile definitions

Definitions describe inputs to runtime behavior; they do not replace server validation or live entity state.

server

{ mode: "normal", // normal, hardcore, or test pvp: false, region: "EU", id: "I", }

server.pvp describes the server. Use in_pvp() when the current map can independently enable PVP.

server.status // Live server-wide events, schedules, and temporary effects

server.status always reads the newest server snapshot. Use it for active event and special-monster state, and see the Server Status reference for its lifecycle and common fields.

game

{ platform: "web", // web, electron, or tauri graphics: true, html: true, cli: false, }

game.platform is web in a browser, electron in the legacy desktop client, and tauri in the current native client. game also owns the game-event methods on, once, all, and remove.

smart

smart.moving // A smart route is active smart.map // Destination map smart.x // Destination x smart.y // Destination y smart.plot // Current planned path smart.edge = 20 // Arrival tolerance smart.use_town = false // Allow town in path search smart.prune.smooth // Smooth redundant points smart.prune.map // Prune routes that leave the destination map

smart exposes the current smart_move state and supported pathfinding options. Internal queue/search fields can change while a route is running; do not retain them as durable state.

safeties

Boolean request-burst safeguards used by chat, loot, and potion helpers. It is true by default. Disabling it does not change server rate limits and can make accidental request bursts disconnect the character.

parent

The containing game window. It exposes low-level runtime objects such as parent.entities, parent.chests, parent.S, and the original parent.character. Existing code that uses these remains compatible, but normal action code should prefer public routines and globals: they normalize data, register Promises before requests, and preserve safeguards.

Nearby runtime collections

parent.entities // Visible characters, monsters, and citizen NPCs by ID server.status // Live replacement-safe view of parent.S get_chests() // Visible chests by ID get_party() // Cached party data get_servers() // Cached server directory get_characters()// Cached account character summaries

Visible entity references become stale after leaving view. Resolve them again with get_entity, get_player, or get_monster before acting.
