Character events

Character events describe things that happen to your own character: incoming attacks, loot, messages, transfers, map changes, action results, and personal status changes.

var listener = character.on("level_up", function (data, event) { game_log("I am now level " + data.level); }); character.once("new_map", function (data) { game_log("Entered " + data.name); }); character.all(function (event, data) { game_log(event + ": " + JSON.stringify(data)); }); character.remove(listener);

character.on(event, callback) and character.once(event, callback) return listener IDs. Remove either with character.remove(id). An ordinary callback receives (data, event); an all-events callback receives (event, data). Listener exceptions are logged without stopping the remaining listeners.

For one event in an async sequence, wait_for_event(character, event, timeout, filter) handles filtering, timeout, and cleanup:

async function wait_for_loot() { var data = await wait_for_event(character, "loot", 5000, function (loot) { return loot.gold > 0; }); game_log("Looted " + data.gold + " gold"); }

new_map

{ name: "main", // G.maps.main in: "main", // Unique instance ID inside instances }

Emitted after the character enters a map. On instances, in differs from the map key.

incoming

{ source: "attack", actor: "AttackerID", target: "YourCharacterName", damage: 1390, // Or heal for a healing action projectile: "momentum", eta: 50, // Expected arrival in milliseconds pid: "abcd1234", }

Emitted when an action is sent toward your character. It describes the launch; use hit for the resolved result.

hit and target_hit

{ source: "attack", actor: "AttackerID", target: "TargetID", damage: 1390, // Or heal pid: "abcd1234", crit: true, kill: false, evade: false, miss: false, avoid: false, reflect: 0, dreturn: 0, poison: false, freeze: false, stun: false, condition: "curse", trigger: "sugarrush", stacked: ["OtherTargetID"], mobbing: 0, unintentional: false, aoe: false, }

hit is emitted when your character is the resolved target. target_hit is emitted when your character owns the resolved attack or heal. Optional false, zero, and empty fields are commonly omitted.

loot

{ id: "ChestID", opener: "CharacterName", goldm: 1.2, dry: false, stale: false, gold: 87, party: true, items: [ { name: "staff", level: 0, looter: "CharacterName" }, { name: "bow", level: 9, looter: null, lostandfound: true }, ], }

Emitted for chests opened by you or your party. Item entries may include additional item properties and PVP loot markers.

cm, pm, and partym

// cm { name: "SenderName", message: { command: "farm", monster: "goo" }, local: true, // Present for same-device local delivery date: Date, // Present for same-device local delivery } // pm and partym { from: "SenderName", message: "Ready", }

CODE messages carry JSON-serializable values. Private and party chat messages carry strings. Use safe_log before rendering untrusted text.

item_sent and item_received

// item_sent { response: "item_sent", name: "ReceiverName", // Documented legacy field to: "ReceiverName", // Directional alias item: "hpot0", q: 10, num: 0, place: "send", success: true, } // item_received { response: "item_received", name: "SenderName", // Documented legacy field from: "SenderName", // Directional alias item: "hpot0", q: 10, num: 12, }

Each transfer emits exactly one event. The legacy name field and the clearer to/from aliases are both retained.

gold_sent and gold_received

// gold_sent { response: "gold_sent", name: "ReceiverName", to: "ReceiverName", gold: 100, amount: 100, place: "send", success: true, } // gold_received { response: "gold_received", name: "SenderName", from: "SenderName", gold: 100, amount: 100, }

gold is the documented transfer field; amount is its compatibility alias. Each transfer emits once.

death, respawn, and level_up

// death {} // respawn { response: "data", place: "respawn", success: true, } // level_up { level: 72, }

stacked and mobbing

// stacked { method: "attack", ids: ["CharacterName1", "CharacterName2"], } // mobbing { intensity: 1, }

Move overlapping characters apart after stacked. mobbing reports the current increased-damage intensity caused by engaging many monsters.

challenge and duel

// challenge "ChallengerName" // duel { challenger: "ChallengerName", vs: "OpponentName", id: "DuelID", }

Action-result event index

Many server responses also become character events. Their payload is the response object after internal routing fields such as cevent are removed. The following names are stable public events:

buy sell craft dismantle destroy exchange_buy mail_sent mail_failed mail_item_taken mail_take_item_failed shell_purchase_complete shell_purchase_failed blessed blessed_fail friend_complete friend_failed unfriend_complete unfriend_failed mluck cx_sent cx_received bank_withdraw bank_store bank_new_pack bank_new_pack_failed giveaway_join picked got_picked pick_failed item_break fishing_fail fishing_success fishing_none mining_fail mining_success mining_none

Response payloads include a response name when they originate from game_response, plus action-specific fields such as name, num, cost, gold, reason, or slot. Code should read the fields it needs and tolerate additional fields.

mail_sent and mail_failed include to and the unique request_id supplied by send_mail, allowing simultaneous mail operations to be correlated without guessing from recipient or timing.

mail_item_taken and mail_take_item_failed include the mail id and the request_id supplied by take_mail_item. Success includes the delivered item; failure includes a concrete reason. Inventory-space and already-claimed responses remain direct routine failures rather than character events.

shell_purchase_complete and shell_purchase_failed include name, quantity, and a correlated request_id. Successful purchases also include cost; failures include reason.

blessed and blessed_fail include cost, result, and the request_id supplied by bless_server. Success also includes blessed_by and the initial remaining minutes; failure includes a concrete reason. The routine normalizes its returned response to the result name while the server also preserves the original raw string response.

friend_complete and friend_failed include name and the request_id supplied by accept_friend_request. Success includes the committed account friends array. The existing friend socket update and friend-request UI remain unchanged.

unfriend_complete and unfriend_failed include name and request_id. Successful removal also includes the updated account friends array.

bank_new_pack and bank_new_pack_failed include pack and shells for shell purchases. Calls made through open_bank_pack also include a unique request_id.

picked, pick_failed, and the fishing/mining result events include a request_id when started through use_skill. Fishing/mining failure events include reason; a *_none event means the timed action completed but produced no resource.
