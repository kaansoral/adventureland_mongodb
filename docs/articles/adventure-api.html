Adventure Land JSON API

The JSON API gives your programs structured access to Adventure Land game definitions, public CODE references, your saved CODE slots, and your Mainframe characters. It does not expose unrestricted character socket commands; run those through contained CODE on Mainframe.

Create a token

  1. Sign in at Adventure Land.
  2. Open Mainframe.
  3. Find Connect an AI.
  4. Press Create token and copy it while it is visible.
  5. Creating another token rotates it and invalidates the previous token immediately.

Treat the token like a password: it controls the account's saved CODE and Mainframe characters. Adventure Land stores only its hash, so the plaintext cannot be shown again. The same token works for the JSON API and MCP.

Call a method

Send JSON with a POST request to https://adventure.land/mcp_api/METHOD. Put the token beside the method arguments:

curl https://adventure.land/mcp_api/get_servers \
  -H 'Content-Type: application/json' \
  -d '{"token":"YOUR_TOKEN"}'

Open GET https://adventure.land/mcp_api for the live method directory, descriptions, and input schemas. Discovery does not require a token.

Use search_game_data to find a record, then get_game_data with its section and exact name to retrieve the complete definition.

POST /mcp_api/search_game_data
{"token":"YOUR_TOKEN","query":"fire resistance","limit":10}

POST /mcp_api/get_game_data
{"token":"YOUR_TOKEN","section":"items","name":"fireblade"}

Results and errors

Successful results contain success: true. Method failures use a structured result with failed: true and a stable reason. The JSON method endpoint returns the structured result as JSON even for an application-level failure, so check the body rather than relying only on the HTTP status.

{
  "failed": true,
  "reason": "not_enough_shells"
}

Unknown and missing arguments fail closed. A token can only read or change CODE and characters owned by its account. Keep polling measured; the account API is not a combat loop.

The live discovery response lists the current request limits. Standard reads, full game-data dumps, and writes have separate token buckets. A throttled request uses HTTP 429, returns reason: "rate_limited", and includes both Retry-After and retry_after_ms.
