Adventure Land tools

The same Adventure Land tools are available through a plain JSON API and through MCP. Use the JSON API for your own programs. Use MCP when an AI client needs a tool directory, input schemas, and structured results.

Both interfaces use one account token and the same permission checks. A token can only read or control characters and CODE slots owned by its account.

Create or rotate your token from an authenticated game session:

var result = await parent.api_call("generate_token"); show_json(result);

Copy the token when it is shown. Generating another token invalidates the previous one.

JSON API

Send a POST request to https://adventure.land/mcp_api/METHOD. Put the token and method arguments in the JSON body:

curl https://adventure.land/mcp_api/get_servers \ -H 'Content-Type: application/json' \ -d '{"token":"YOUR_TOKEN"}'

Available methods:

get_servers get_game_data list_codes get_code save_code delete_code mainframe_list_characters mainframe_get_character mainframe_link_character mainframe_disconnect_character mainframe_get_logs

MCP

Connect an MCP client to https://adventure.land/mcp and send the token as an HTTP bearer token. The server supports the current stateless MCP protocol and the previous Streamable HTTP handshake protocol.

URL: https://adventure.land/mcp Authorization: Bearer YOUR_TOKEN

The MCP tool names are the same as the JSON API method names. Tool results include both readable text and structured JSON.

Mainframe

Mainframe runs one character's saved CODE inside its own small machine. The character has no internet connection. Game actions pass through a narrow Adventure Land connection, and smart_move uses the Mainframe navigation service instead of running the exhaustive browser pathfinder.

A new access window costs 1 Shell and lasts 60 minutes. The Shell is charged before the character starts. Disconnecting does not pause the window. Reconnecting the same character during an active window costs nothing.

Link a character with a unique request ID, one owned CODE slot, and an optional live server:

POST /mcp_api/mainframe_link_character { "token": "YOUR_TOKEN", "character": "YourCharacter", "request_id": "your-unique-request-0001", "code_slot": "1", "server": "US I" }

Repeating the same request ID is safe. Mainframe never uses the name alone as the character identity, never replaces a different assignment, and refuses to start a character that is already in the game.

CODE compatibility

Mainframe provides the public CODE function directory without a browser DOM. Combat, movement, inventory, crafting, social, mail, trade, storage, and event methods use the normal game actions. Drawing, buttons, focus, and other visual-only methods are harmless headless operations. Character control and CODE uploads pass through the trusted Mainframe service. Starting another character charges its own access window, and commands can only reach another active Mainframe character on the same account.

Use mainframe_get_character for confirmed position, map, health, runtime limits, disk activity, and recent performance. Each active character reports its separate machine identity, memory use, CPU throttling, I/O counters, and containment checks. Requested action counters show what CODE attempted; observations show what the game server actually reported.
