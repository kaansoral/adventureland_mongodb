Mainframe

Mainframe keeps your characters running Adventure Land CODE when your browser is closed. A character you run from the Mainframe page gets its own isolated machine and uses one of your saved CODE slots.

Open Mainframe to choose a character, CODE slot, and live realm. Mainframe is also visible in COM and on /comm.

Cost

Steam accounts receive 250 free Mainframe hours. The allowance is shared by every Adventure Land account linked to the same Steam account. Mainframe uses one free hour instead of one Shell at renewal.

A direct run prepays 60 minutes. Mainframe uses shared Steam time first, then charges 1 Shell. While the assignment remains running, it renews automatically until you explicitly disconnect the character or the account cannot pay.

At renewal, one active character receives 60 minutes, two receive 50 minutes, three receive 45 minutes, and four receive 40 minutes. Mainframe counts active characters only at that boundary. Starting or stopping an included character does not change the window already paid for.

Disconnecting disables future renewals but does not refund or pause the current prepaid window. Reconnecting the same character before that window ends costs nothing and enables renewal again.

If running CODE calls start_character, Mainframe can place up to three additional characters inside that caller's machine, for four total. They share the caller's prepaid window instead of opening separate paid windows. The first child start reconnects the caller once while Mainframe changes it to a shared machine. Calling stop_character stops only that child; disconnecting the root character stops every included character. Starting characters directly from the Mainframe page still gives each one a separate machine and charge.

A running assignment is meant to survive maintenance. Mainframe restores it after Adventure Land HTTP restarts, controller restarts, host maintenance, and machine replacement. Recovery can briefly reconnect the character, but it does not mark the assignment as stopped.

Mainframe refuses to load a character that is already active elsewhere. It never replaces a different running assignment. A character can have only one Mainframe assignment at a time.

What CODE can do

Mainframe supports the public CODE function directory without a browser page or DOM. Combat, movement, inventory, crafting, social, mail, trade, storage, and event functions use normal game actions. UI-only calls such as buttons, drawing, and focus do not affect gameplay.

smart_move uses Mainframe navigation instead of running the browser's exhaustive pathfinder. Your code keeps the same public call.

await smart_move("bank"); await smart_move({ map: "main", x: -100, y: -20 });

Containment

Every dedicated character, or shared group of up to four workers, runs with an isolated machine identity, read-only system image, memory, CPU, and disk limits, syscall filtering, and no internet interface. Workers inside a shared machine also have separate Worker identities and memory limits. Shared guest memory grows from 128 MiB to at most 192 MiB as workers are added; the machine keeps the same fixed 10% CPU limit. Character actions can reach Adventure Land only through the Mainframe bridge. Mainframe reports requested actions separately from confirmed game state, so you can tell the difference between "CODE asked" and "the server accepted."

If CODE loops forever, uses too much memory, or repeatedly writes, its machine stays isolated. In a shared machine, each CODE runtime has its own Worker and memory limit. An unresponsive Worker is stopped and restarted without restarting healthy workers. A complete machine failure can stop the group, but cannot reach another Mainframe machine.

Status and logs

The Mainframe card shows the last game disconnect reason when the server supplies one. Call cost is that worker's current CPU use as a percentage of its fixed worker CPU budget; it is not a Shell charge.

CODE log contains output written by character CODE. Mainframe log contains starts, automatic renewals, server changes, explicit stops, recovery, and unexpected Worker restarts. Failures and restarts are red. Both logs remain available for 30 days after a worker or machine stops.

Automation interfaces

Your own service can control Mainframe through the JSON API. AI clients can use the same operations through MCP. Both interfaces enforce the same account ownership, billing, assignment, and CODE-slot checks as the web page.

The Connect an AI panel on Mainframe creates, replaces, copies, and revokes the account token. The MCP gives compatible clients game docs, CODE guidance, and account tools; see Adventure Land MCP for AI for setup.

Use a unique request_id when linking a character. Reuse that ID only when retrying the same request. This makes a lost response safe to retry without charging twice.

{ "character": "YourCharacter", "request_id": "my-service:link:000001", "code_slot": "1", "server": "US I" }

Cyberland terminal

The terminal inside Cyberland is a separate in-world machine. Run its visible commands through CODE with mainframe_command. The Promise resolves with the terminal's reply.

var response = await mainframe_command("hello"); game_log(response.reply);
