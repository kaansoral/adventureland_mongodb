The CODE runtime

Your code runs inside its character's CODE frame. The public function directory is the authoritative list of supported global routines. Every listed routine has its signature, return contract, notes, example, and shipped source.

Core globals:

character // Your live character proxy G // Game definitions: items, skills, maps, monsters, recipes, and more server // { mode, pvp, region, id } game // { platform, graphics, html, cli } smart // Current smart_move state and pathfinding options safeties // Request-burst safeguards; true by default

Promises

Server actions return native Promises. Registering the response happens before the request is emitted, so even an immediate server response is correlated with the correct call.

async function attack_once(target) { try { var result = await use_skill("attack", target); game_log("Attack accepted: " + result.damage); } catch (error) { game_log("Attack failed: " + error.reason); } }

By default, successful actions fulfill and failures reject with a structured object containing failed: true and reason. Call mode_resolve_all() once at startup only when old code requires every action to fulfill:

mode_resolve_all(); attack(target).then(function (result) { if (result.failed) game_log(result.reason); });

Calls using the same response channel are queued in request order. The queue is bounded: if abusive or broken code overflows it, the oldest Promise settles with queue_overflow instead of hanging forever.

Completion-aware routines

Most actions settle when the server accepts or refuses the action. Routines with a longer lifecycle wait for the meaningful completion point:

async function run_sequence() { await start_character("Merchant", "merchant_code"); // CODE runner is active await smart_move("bank"); // Destination reached await transport("main", 0); // Destination map loaded await town(); // Town channel completed await exchange(0); // Reward slot updated await accept_friend_request("Wizard"); // Friendship created await send_mail_complete("Merchant", "Route", "Meet at the bank"); // Mail stored await take_mail_item("ML_your_mail_id"); // Attachment in inventory await buy_with_shells_complete("computer", 1); // Account and inventory updated await unfriend_complete("FormerFriend"); // Both accounts updated await wait_for(function () { return get_player("Wizard"); }, 5000); await wait_for_event(character, "new_map", 5000); } run_sequence();

These routines reject on interruption, disconnection, or their documented timeout instead of leaving a Promise pending forever. A repeated identical active transport or smart route shares the existing trip; a conflicting route fails or interrupts according to that function's reference.

Events and callbacks

Use character.on, character.once, character.all, character.remove, and the equivalent game event methods for current event code. Use wait_for_event when one event belongs to an async sequence. The named on_* and handle_* functions remain supported override points for existing code.

character.on("cm", function (data) { game_log(data.name + ": " + JSON.stringify(data.message)); }); game.on("game_event", function (event) { show_json(event); });

Compatibility

Established names and call forms remain in place. Functions such as use, destroy_item, is_player, is_pvp, and callback arguments such as smart_move(destination, on_done) are documented as compatibility APIs. New code can use their clearer replacements without breaking old code.

Persistence and shared code

set("farm", { monster: "goo", kills: 12 }); var farm = get("farm"); pset("route", "winterland"); var route = pget("route"); load_code("globals"); var helpers = require_code("helpers");

get/set store JSON-serializable browser-local values. pget/pset use the platform's raw persistent string storage. load_code deliberately adds declarations to the current global scope; require_code isolates a module and returns its exports.

Low-level socket access

get_socket() is available for listening to low-level events. Prefer the public action functions for requests: a raw socket emit does not register a CODE Promise, correlate a response, or apply the normal client safeguards.
