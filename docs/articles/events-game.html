Game events

Game events describe ambient or server-wide activity visible to this client: combat around you, map changes, trades, public purchases, spawns, chat, deaths, and server notices.

var listener = game.on("level_up", function (data, event) { game_log(data.name + " is now level " + data.level); }); game.once("event", function (data) { game_log("Event: " + data.name); }); game.all(function (event, data) { game_log(event + ": " + JSON.stringify(data)); }); game.remove(listener);

game.on(event, callback) and game.once(event, callback) return listener IDs. Remove either with game.remove(id). An ordinary callback receives (data, event); an all-events callback receives (event, data).

wait_for_event(game, event, timeout, filter) is available when an event belongs to an async sequence.

event

{ name: "snowman", map: "winterland", // Optional x: 12, // Optional y: 88, // Optional }

Server event announcements use this event. The event name and optional location depend on the live event.

action

{ source: "attack", actor: "AttackerID", target: "TargetID", damage: 1390, // Or heal projectile: "momentum", eta: 50, pid: "abcd1234", }

Emitted when a visible action launches. The actor and target can be character names or monster IDs. Rays and instant skills can use fields such as ray and instant instead of projectile travel.

hit

{ source: "attack", actor: "AttackerID", target: "TargetID", damage: 1390, // Or heal crit: false, kill: false, evade: false, miss: false, avoid: false, reflect: 0, dreturn: 0, condition: "curse", trigger: "sugarrush", stacked: [], mobbing: 0, unintentional: false, aoe: false, }

Emitted for resolved visible combat. Optional false, zero, and empty fields are commonly omitted.

trade and sale

// trade { seller: "SellerName", buyer: "BuyerName", item: { name: "staff", level: 9 }, num: 12, slot: "trade8", } // sale: the same shape, emitted locally when your character is the seller

buy, sell, sbuy, and fbuy

{ name: "CharacterName", item: { name: "pants", level: 0 }, }

buy and sell are ordinary NPC activity. sbuy is a Ponty purchase; fbuy is a Lost and Found purchase.

item_sent, gold_sent, and cx_sent

// item_sent { sender: "SenderName", receiver: "ReceiverName", item: { name: "hpot0", q: 10 }, num: 12, fnum: 0, } // gold_sent { sender: "SenderName", receiver: "ReceiverName", gold: 100, } // cx_sent { sender: "SenderName", receiver: "ReceiverName", cx: "hat999", }

These are visible ambient transfer events. Your own transfer completion is also reported once through the corresponding character event.

level_up and death

// level_up { name: "CharacterName", level: 72, } // death { id: "CharacterNameOrMonsterID", }

chat

{ from: "CharacterNameOrOwnerID", message: "Hello", }

Public chat text is untrusted. Use safe_log before rendering it.

new_map

{ name: "main", in: "main", }

This mirrors the character event after your client enters a new map.

mluck

{ name: "MerchantName", item: { name: "staff", level: 0 }, num: 12, }

api_response

{ type: "servers_and_characters", servers: [], characters: [], }

Emitted for asynchronous API information delivered to the game. Fields depend on type.

pvp_list and ccreport

pvp_list carries the current PVP list when the server supplies one to CODE. ccreport carries the server call-cost report object.

Dynamic events

Some server UI and response messages declare their event name at runtime. When a message supplies event: true, its type or response becomes the game event name; when it supplies a string, that string is the name. The complete stable index currently includes:

event action hit trade sale buy sell sbuy fbuy item_sent gold_sent cx_sent level_up death chat new_map mluck api_response pvp_list ccreport

Dynamic payloads can gain fields over time. Read the fields your code needs and tolerate additions.
