Practical geometry

Use distance(a, b) for gameplay range checks. It understands entity dimensions and returns edge-to-edge distance rather than blindly measuring sprite centers.

async function attack_nearest_in_range() { var target = get_nearest_monster(); if (target) { game_log("Range: " + distance(character, target)); if (is_in_range(target, "attack")) await attack(target); } } attack_nearest_in_range();

Use ordinary Euclidean distance when you specifically need the distance between two mathematical points:

function point_distance(a, b) { var dx = b.x - a.x; var dy = b.y - a.y; return Math.sqrt(dx * dx + dy * dy); }

The direction from A to B in radians is Math.atan2(b.y - a.y, b.x - a.x). Because positive Y points downward, positive angles turn visually clockwise on the map.

function point_at_distance(a, b, units) { var angle = Math.atan2(b.y - a.y, b.x - a.x); return { x: a.x + Math.cos(angle) * units, y: a.y + Math.sin(angle) * units }; }

Geometry alone does not prove a route is walkable. Use can_move_to for a direct segment and smart_move for pathfinding. For skills, prefer is_in_range(target, skill); skill ranges can differ from the character's ordinary attack range.
