start_character(name, code_slot_or_name)

Starts another character from your account in CODE-only mode, optionally with a code slot or file name.

Returns: Promise resolving when the character is running, or immediately when it already has a local runner. Rejects when the name or slot is invalid, the character is already active elsewhere, startup is interrupted, or the timeout expires.

Promise failures: Unless a function-specific note says otherwise, failures reject with an object containing failed: true and a reason. After mode_resolve_all(), the same failures fulfill instead.

Notes: Repeated calls for the same local character share its startup or reuse its active runner instead of creating duplicates.

Mainframe: The first child call changes the caller from a dedicated machine to a shared machine and can briefly reconnect it. Up to three other owned characters can run as included workers, for four characters total. Each uses its own CODE slot, game session, Worker identity, memory limit, and realm-limit authentication, but shares the root character's prepaid Mainframe window and fixed machine CPU budget. Starting the same character directly from the Mainframe page remains the more isolated, separately charged option.

At the next renewal, one Shell or free Steam hour buys 60, 50, 45, or 40 minutes when 1, 2, 3, or 4 characters are active. Starting or stopping a child does not reprice the current window. If the root disconnects or cannot renew, every included worker stops. Use stop_character(name) to stop only one child. Mainframe rejects a fifth character, a character active elsewhere, an unknown CODE slot, or a character from another account.

Example:

async function example() { await start_character("Merchant", "merchant_code"); } example();
