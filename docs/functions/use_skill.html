use_skill(name, target, extra_arg, timeout_ms)

Uses a named skill with an optional target and skill-specific extra argument.

Returns: One Promise. Pickpocket, fishing, and mining wait for their final result. Other skills resolve when the server accepts the skill request; a projectile may still be in flight.

Promise failures: Unless a function-specific note says otherwise, failures reject with an object containing failed: true and a reason. After mode_resolve_all(), the same failures fulfill instead.

Notes: Targets may be entity objects, character names, monster IDs, coordinate arrays for blink, or arrays for multi-target skills. If target is omitted, get_target() is used. Multi-target skills return one Promise, not an array. The optional timed-action timeout defaults to 20,000ms. Final timed-action results include response, place, request_id, and success; fishing/mining also include found.

Example:

async function example() { var result = await use_skill("fishing", null, null, 20000); if (result.found === false) game_log("Nothing caught this time"); } example();

Paladin Aura: At level 60, pass the aura state as the second argument, not extra_arg. Choose "bulwark" (armor and HP), "sanctuary" (resistance and MP), "zeal" (damage output and attack frequency), or "warding" (elemental and status resistances, and reduced MP costs).

async function select_aura() { try { var result = await use_skill("paladin_aura", "zeal"); game_log("Aura: " + result.aura); } catch (error) { game_log("Aura change failed: " + error.reason); } } select_aura();

Switching costs no MP and has a 500ms cooldown. The aura stays active passively; do not recast it to refresh its 60-second condition. Switching removes your previous aura's contribution immediately. Only the strongest nearby source of each state applies, while different states from different Paladins can coexist. See G.skills.paladin_aura.states for the stat values.
